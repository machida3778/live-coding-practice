# 24 【模擬本番】ラティスとViterbiで形態素解析  (目標 60分 / ★★★★)

MeCab のような「コスト最小化による形態素解析器」の簡易版を作ります。
辞書 (単語ごとの **単語コスト**) と品詞間の **連接コスト** 表から、文のあり得る分割をすべて表すラティスを作り、
総コスト最小の分割を Viterbi アルゴリズムで求めます。パートごとにテストがあります (部分点あり)。

## コストの定義
文を単語列 `w_1, ..., w_m` に分割したときの総コスト:
```
総コスト = Σ_k 単語コスト(w_k) + Σ_{k=0..m} 連接コスト(品詞(w_k), 品詞(w_{k+1}))
```
- `w_0` は文頭 `BOS`, `w_{m+1}` は文末 `EOS` (どちらも品詞名として `"BOS"`, `"EOS"` を使い、単語コストは 0)
- 連接コスト表に **無い組み合わせのコストは 0**。コストは負の値もあり得る

---
## Part 1: 辞書ファイルの読み込み (関数)
共通ルール: **空行と `#` で始まる行は無視**。各フィールドの前後の空白は除去する

### `load_dictionary(path) -> dict[str, list[tuple[str, int]]]`
- 各行 `表層,品詞,単語コスト` (例 `すもも,名詞,1000`)
- 戻り値: `{表層: [(品詞, コスト), ...]}`。同じ表層が複数行あれば **ファイル順に** リストに追加

### `load_connection(path) -> dict[tuple[str, str], int]`
- 各行 `左品詞 右品詞 コスト` (区切りは 1 個以上の空白またはタブ)
- 戻り値: `{(左品詞, 右品詞): コスト}`

同梱の `dict.csv`, `matrix.txt` で試せます。

---
## Part 2: 辞書引き `class LatticeTokenizer(dictionary, connection, unk_cost=10000)`
### `lookup(text, i) -> list[tuple[str, str, int]]`
- `text` の位置 `i` から始まる (= `text[i:]` の接頭辞である) 辞書語をすべて `(表層, 品詞, 単語コスト)` で返す
- 並び順: 表層の長さの昇順、同じ表層ならその表層の辞書リストの順
- **1 つも無い場合だけ** 未知語ノード `[(text[i], "未知語", unk_cost)]` を返す (未知語は常に 1 文字)
- 辞書は数万語、テキストは数千文字でも高速に動くこと (辞書全体を毎回走査しない)

---
## Part 3: 解析 (Viterbi)
### `tokenize(text) -> list[tuple[str, str]]`
- 総コスト最小の分割を `[(表層, 品詞), ...]` で返す。各位置の候補は `lookup` で得られるノード
- 空文字列なら `[]`
- 最小コストの分割が複数ある場合はどれを返してもよい (公開・非公開テストの固定文では同点は起きない)

### `best_cost(text) -> int`
- 最小の総コスト (空文字列なら `連接コスト(BOS, EOS)`)

---
## 例 (同梱の dict.csv / matrix.txt を使用)
```python
>>> D = load_dictionary("dict.csv"); C = load_connection("matrix.txt")
>>> D["も"]
[('助詞', 300), ('名詞', 2500)]
>>> C[("名詞", "助詞")]
-300
>>> tok = LatticeTokenizer(D, C)
>>> tok.lookup("すもももも", 0)
[('す', '名詞', 2000), ('すもも', '名詞', 1000)]
>>> tok.lookup("パクシャ", 0)
[('パ', '未知語', 10000)]
>>> tok.tokenize("すもももももももものうち")
[('すもも', '名詞'), ('も', '助詞'), ('もも', '名詞'), ('も', '助詞'), ('もも', '名詞'), ('の', '助詞'), ('うち', '名詞')]
>>> tok.best_cost("すもももももももものうち")
3600
```

## 面接官が聞きそうなこと
- 全分割を列挙すると計算量はどうなる? Viterbi だとどうなる?
- 辞書引きを速くするデータ構造は? (Trie, Double-Array, 共通接頭辞検索)
- MeCab は未知語をどう扱っている? (文字種ごとのグルーピング) この実装の未知語処理の弱点は?
- コスト (単語コスト・連接コスト) はどうやって決める? (CRF などで学習)
- N-best 解を出すにはどう拡張する?
